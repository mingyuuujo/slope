# 공종 통합 지형·3D·물량 워크플로우

> 후속 구현을 위한 설계 기록 · 2026-10-17. 현재 구현된 기능이 아니다.

## 의도

모든 공종의 수량산출 기능을 구현한 뒤, 프로젝트 전체를 하나의 지형도와 3D 모델에서 검토한다. 공종 버튼을 선택하면 해당 공종의 객체만 강조하거나 분리해 보여주고, 같은 선택에 대응하는 물량·산출근거를 표시한다. 화면에서 보는 수량과 공종별 Excel은 각 공종의 확정 계산 결과를 참조한다.

재하성토공에 있던 영상지도·현장사진 입력과 브이월드 3D 전환 UI는 2026-10-17에 제거했다. 현재 재하성토공의 DXF 평면도와 설계 3D 모델은 유지한다. 기존 `SurchargeFill/js/vworld-aerial.js`, `SurchargeFill/js/terrain3d.js`, `SurchargeFill/terrain-frame.html`은 후속 검토를 위한 참고 코드이며 현재 화면에서 호출하지 않는다. 이 코드를 통합 화면에 그대로 복사하기 전에 API 계약, 좌표 변환, 성능, 배포 범위를 다시 검토한다.

## 화면 구조

1. **프로젝트 장면**: 지형도/영상지도와 전체 공종 3D 모델을 한 화면에 배치한다. 2D 지도와 3D 카메라는 같은 프로젝트 좌표를 사용한다.
2. **공종 선택기**: 공종별 버튼 또는 목록으로 표시·숨김·강조를 제어한다. 여러 공종 동시 선택과 전체 보기, 구역 선택을 지원한다. 선택·카메라 이동은 표시만 바꾸고 수량을 재계산하지 않는다.
3. **물량 패널**: 선택한 공종과 구역의 단위, 2D/3D 기준, 단계, 총량·증분량·제거량, 계산 시각과 최신성 상태를 표시한다. 행을 선택하면 해당 3D 객체를 강조하고, 3D 객체를 선택하면 대응하는 산출근거를 연다.
4. **검토 패널**: 연결되지 않은 구역, 좌표계 불일치, 오래된 계산 결과, 누락된 공종 자료를 명확하게 표시한다.

## 데이터 연결 원칙

- 프로젝트·구역·공종·단계·모델 객체는 고유 ID로 연결한다. 구역명은 표시용이다.
- 공종별 확정 결과를 통합 화면이 읽는다. 통합 화면에서 별도 수량식을 만들어 같은 물량을 다시 계산하지 않는다.
- 객체에는 `projectId`, `zoneId`, `tradeId`, `stageId`, `material`, `sourceResultId`를 연결한다. 공종별 계산 기준과 단위가 다른 결과를 합산할 때는 중복·공제 관계를 먼저 정의한다.
- 화면, 3D, 공종별 산출서가 동일한 계산 결과 버전을 참조한다. 입력 해시·엔진 버전·소스 해시가 없거나 입력이 달라진 결과는 확인 불가 또는 재계산 필요로 표시한다.
- GeoSettle 누적 성토 높이에서 표층처리공 배수층과 재하토를 구분한다. 배수층 시공량은 표층처리공, 재하토 시공량은 재하성토공, 배수층 제거량은 재하성토공의 제거 결과에 둔다. 전체 물량에서 같은 체적을 두 번 합산하지 않는다.
- 다른 공종의 계산을 수정하거나 다시 실행해도 기존 유효 결과를 덮어쓰지 않는다. 변경된 공종·구역만 최신성을 다시 판단한다.

## 지형도·영상·3D

- 브이월드 및 국토교통부의 사용 가능한 API를 조사해 영상지도, 지형·고도, 3D 배경을 검토한다. 구현 시점에 공식 문서의 제공 범위, 인증 방식, 사용 조건, 표시 의무, 호출 한도를 다시 확인한다. API 키는 용도와 도메인에 맞게 관리하며 비밀 키는 브라우저 코드에 넣지 않는다.
- DXF 수평 좌표계와 표고 기준(DL/EL)을 별개로 기록한다. 좌표계 미상 자료를 추정해서 영상지도 위에 놓지 않는다. 좌표 변환 결과와 원본 좌표를 함께 보존한다.
- 현장 정사영상·사진은 실제 경계 좌표와 출처가 있을 때만 지도에 정합한다. 사진 픽셀을 구역 범위에 임의로 맞춰 설계 위치가 정확하다고 표시하지 않는다.
- 설계 3D, 지형 표면, 영상 텍스처는 서로 다른 레이어다. 지형 표면은 설계고나 준공고를 대신하지 않는다. 부지 밖 높이, 지형 보정, 단계별 성토고의 기준을 화면에 명시한다.
- 공종 객체의 색·투명도·하이라이트·선택 범례를 공통 규칙으로 관리한다. 카메라와 표시 전환은 계산 Worker를 재호출하지 않는다.

## 구현 순서

1. 공종별 결과 계약과 ID·좌표·단위·버전 필드를 정리하고, 통합 화면에서 읽을 수 있는 경량 장면 목록을 만든다.
2. 지도 없이 전체 공종 3D·공종 선택·구역 선택·물량 패널을 구현한다. 선택 객체와 결과 행의 상호 연결을 확인한다.
3. 좌표계가 확인된 프로젝트에 한해 지형도/영상지도를 별도 레이어로 추가한다. API 실패 시에도 설계 모델과 수량 검토는 가능하게 한다.
4. 많은 구역과 공종을 가진 실제 DXF 규모에서 로딩, 카메라 이동, 선택 반응, 메모리·GPU 사용량, 저장·복구를 측정한다.
5. 공종별 Excel과 통합 화면의 수량·단위·최신성 상태를 대조한다. 2D/3D 기준이 다른 결과는 구분해 보여준다.

## 보류할 설계 결정

- 공종 간 중복 체적의 공제 규칙과 통합 총량의 범위
- 단계별 시점이 다른 공종을 하나의 타임라인에 맞추는 방법
- 지형·영상 공급원과 오프라인/현장 사진 대체 경로
- 대형 모델의 타일·구역 단위 로딩과 캐시 상한

후속 구현 요청 시 이 문서와 `design.md`, `quantity-architecture.md`, 각 공종 `AGENTS.md`를 먼저 확인한다.
