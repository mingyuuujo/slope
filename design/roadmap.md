# 적용 순서와 완료 기준

문서 작성만으로 화면이 통일된 것은 아니다. 각 단계를 공종별로 작게 적용하고 해당 변경과 직접 연결된 부분을 확인한다.

## 0. 기준 확보

- [x] 기존 `design.md`를 보관하고 목표 규칙·현재 구현·공종별 예외를 분리한다.
- [x] [실제 화면 구조 점검](implementation-audit.md)을 기록한다.
- [ ] GeoSettle을 포함한 모든 화면의 데스크톱·좁은 화면을 같은 조건에서 기록한다. 메인과 세 수량 화면은 1440px·390px 기록 완료.
- [ ] 공통 CSS와 공종별 중복 스타일, 실제 토큰 사용 위치를 확인한다.

## 1. 공통 작업 틀

- [ ] `shared/`에 색·글자·간격·초점 토큰을 정의하고 화면별 기존 변수에 순차 연결한다.
- [ ] 좌측 탐색의 현재 위치, 내부 메뉴, 다른 도구 영역을 같은 순서로 맞춘다.
- [x] 세 수량 화면에 내부 메뉴 현재 위치와 공종 전환을 적용한다.
- [ ] 제목·상태·툴바의 크기·간격·버튼 우선순위를 맞춘다.
- [ ] 좁은 화면에서 탐색과 툴바가 입력 공간을 가리지 않게 한다.

## 2. 입력과 자료

- [ ] DXF/JSON 카드의 이름·상태·단위·교체 패턴을 통일한다.
- [ ] 평면도와 가져오기 패널의 최소 폭·높이·빈 화면을 맞춘다.
- [ ] 구역·장비·재료의 추가/삭제, 유효성 오류, 실행취소 표시를 정리한다.
- [ ] 입력 변경 후 결과의 `재계산 필요` 상태를 같은 의미로 쓴다.

## 3. 결과와 검토

- [ ] 요약·단계·구역 표에 2D/3D 기준, 단위, 계산 시각·출처를 일관되게 표시한다.
- [ ] 표 머리글 고정, 숫자 정렬, 빈 값, 소계/합계, 구역 자연 정렬을 정리한다.
- [ ] 2D/3D 레이어·범례·선택 정보·보기 조작 위치를 맞춘다.
- [ ] Excel 내보내기가 현재 표시 기준과 같은 결과를 사용함을 명확하게 표시한다.

## 4. 유지

- [ ] 키보드, 초점, 좁은 화면, 긴 파일명, 많은 구역, 로딩·오류·저장 실패를 화면별로 확인한다.
- [ ] 공통 부품은 공종별 덮어쓰기보다 `shared/`를 우선 사용하고 남는 예외는 기록한다.
- [ ] 새 공종은 이 목록과 `design.md`를 시작점으로 사용한다.

## 변경 완료 기준

화면을 바꿨다면 (1) 빈 자료의 시작 상태, (2) 입력→계산→결과→내보내기 순서, (3) 입력 변경 뒤 결과 상태, (4) 긴 표와 좁은 화면, (5) 키보드 초점, (6) 공종 이동 후 복귀 상태를 확인하고 결과를 작업 보고에 적는다. 계산이나 큰 DXF를 건드린 작업은 `AGENTS.md`의 성능 측정 조건도 따른다.
