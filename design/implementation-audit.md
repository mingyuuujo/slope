## 이번 변경

- 메인 카드의 이미지·제목·행동 영역을 더 촘촘한 도구 목록으로 조정했다. 실행 링크와 분류 동작은 유지한다.
- 세 수량 화면의 사이드바에 내부 메뉴와 다른 도구를 같은 순서로 제공한다. 빠졌던 표층처리공 이동을 추가했다.
- `shared/tool-workspace.css`에서 세 화면의 탐색 선택 상태, 헤더·툴바 간격, 모바일 내부 메뉴를 공통 관리한다.
- `shared/tool-workspace.js`는 URL 해시로 현재 내부 메뉴를 표시하고 프로그램 메뉴의 명령을 기존 버튼으로 전달한다. 입력이나 계산 데이터를 직접 읽거나 쓰지 않는다.
- 세 수량 화면에 프로그램 메뉴를 추가했다. 메뉴는 기존 버튼이나 화면 섹션으로 연결되며 복구·JSON·실행취소 명령을 메뉴에서 찾을 수 있게 했다. 메뉴 명령 전달은 `shared/tool-workspace.js`가 담당한다.
- 화면 원본과 `dist/`의 해당 HTML·CSS·JS를 동일하게 갱신했다.

## 다음 구조 작업

1. 표층처리공이 `SurchargeFill/app.css` 전체를 가져오는 의존성을 줄인다. 공통 레이아웃만 `shared/`로 옮기고 고유 스타일은 공종에 둔다.
2. 세 수량 화면의 자료 가져오기 카드와 결과 상태를 공통 패턴으로 정리한다. 실제 파일 검증·계산 상태는 각 공종 코드가 제공한다.
3. GeoSettle의 탐색·상태·표 토큰을 단계별로 연결한다. 설계 입력 탭의 동작은 유지한다.
4. 데스크톱·좁은 화면의 실제 브라우저 캡처를 확보해 길이·잘림·초점 상태를 조정한다.

## 검증과 한계

- 변경한 세 화면의 HTML에서 ID 중복, 내부 메뉴 링크 대상, 공통 파일 중복 로드를 검사했다.
- 로컬 호스팅에서 세 화면과 공통 CSS·JS가 HTTP 200으로 제공됨을 확인했다.
- 공통 JS의 기본 메뉴 선택과 해시 변경을 별도 DOM 모형으로 확인하고 Node 문법 검사를 통과했다.
- 로컬에 선언된 Playwright 의존성을 임시 설치하고 Edge headless로 메인과 세 수량 화면을 1440px·390px에서 열었다. 여덟 화면 모두 페이지 오류가 없었고 문서 너비가 뷰포트를 넘지 않았다. 세 수량 화면의 내부 메뉴 선택과 해시 이동을 확인했다.
- 스크린샷으로 메인 도구 목록과 공종 화면의 탐색·자료 배치를 확인했다. 실제 DXF·JSON을 넣은 계산 흐름과 키보드 전체 동선은 이번 시각 변경의 검증 범위에 포함하지 않았다.
- 메인 분류 필터의 수량산출 6개 표시와 메인 → 표층처리공 → 재하성토공 → 연직배수공 이동도 Edge에서 확인했다.
- 검증용으로 설치한 `SurchargeFill/node_modules`의 정리 명령은 자동 승인 검토에서 거부됐다. 설치물은 그대로 남아 있으며 소스·설정 파일은 변경하지 않았다.
